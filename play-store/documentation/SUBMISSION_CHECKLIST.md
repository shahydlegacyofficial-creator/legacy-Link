# Submission checklist

## Prepared in the kit

- [x] Legacy Studios store identity and supplied support/privacy email.
- [x] English title, descriptions and version-code-6 release note.
- [x] Original brand icon and graphics source tooling.
- [x] Android 16/API 36 build configuration with HTTPS-only Play flavor.
- [x] Prominent notification-sharing disclosure, privacy-policy link and local-data control.
- [x] Android restricted-settings troubleshooting and App info shortcut.
- [x] Public privacy, support and deletion HTML sources.
- [x] Signed AAB build tooling; private upload key is excluded from GitHub.
- [x] Data safety worksheet, App content guidance, reviewer instructions and test plan.

The generated asset/build validation report records the final file checks and test results. A checked preparation item does not represent Google approval or completion of an owner-only Console step.

## Finish in your Play Console

- [ ] Verify the developer account and supply the real legal/trader/contact details required for your account and regions.
- [ ] Confirm mv.legacy.link is the intended new app ID, or that the upload key matches any existing Play app before uploading an update.
- [ ] Back up the private upload key and credentials securely. Configure Play App Signing when creating the new app.
- [ ] Open the published privacy/support/deletion URLs without login and confirm the email is monitored.
- [ ] Review the Data safety worksheet against the actual assistant receiver and all AI integrations; certify only confirmed answers.
- [ ] Supply stable HTTPS reviewer access and test credentials privately in Console.
- [ ] Complete App access, financial/health/other applicable declarations and IARC content rating.
- [ ] Choose intended audience, price, countries and device distribution. This kit supplies phone assets only.
- [ ] Upload the signed play.aab to internal testing and complete physical-device testing, including the user's affected phone.
- [ ] If your account requires it, complete a closed test with at least 12 opted-in testers for 14 continuous days and apply for production access.
- [ ] Review the automated pre-launch report, fix findings, then submit the release for Google's review.

Do not upload the personal debug APK to Google Play. Do not claim that an emulator test is a completed closed test or an independent security assessment.
